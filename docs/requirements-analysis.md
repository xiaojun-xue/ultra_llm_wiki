# LLM Wiki 需求分析文档

## 1. 项目背景与目标

### 1.1 项目背景

嵌入式开发团队积累了大量技术文档（设计说明书、通信协议）、源代码（C/驱动）、原理图（PCB）。这些资料散落在不同位置，缺乏统一检索能力。Claude Code 时代，AI 助手需要理解项目上下文才能提供有价值的建议。

### 1.2 核心目标

1. **统一存储** — 文档/代码/原理图集中管理
2. **语义检索** — 理解意图而非关键词匹配
3. **知识关联** — 自动发现文档间关系
4. **AI 集成** — Claude Code 可直接查询

## 4. 支持文件格式

| 类型 | 扩展名 | 解析器 |
|------|--------|--------|
| 源代码 | .c .h .cpp .java .py .js .rs .go | CodeParser |
| 文档 | .md .txt .pdf .docx .rst | MarkdownParser/PdfParser |
| 配置 | .ini .cfg .json .yaml | ConfigParser |
| 原理图 | .sch .schdoc .brd | SchematicParser |

## 5. 非功能需求

| 指标 | 目标 | 说明 |
|------|------|------|
| API 响应 | p95 < 500ms | 不含下载 |
| 向量检索 | p95 < 200ms | pgvector |
| 文件大小 | ≤ 100MB | Nginx 配置 |
| 并发用户 | 100+ | 水平扩展 |
| 系统可用性 | 99% | 单节点 |
